拾链  1.1.8（Relinker）

一个小工具：给 AE 工程里丢了的素材（图片/视频/音频）重新接上。
点【选工程】挑一个 .aep 即可：它自己去找、自己去连，最后给出一份报告。

================================================================
这版能干什么
================================================================

· 扫一个 .aep 里所有素材引用，把「找不到文件」的那些按文件名在本机找回来并重新接上；
· 默认先复制一份再改（again_fixed.aep），原工程一个字节都不动；
· 跑完给结论一行 + 三宫格（已在线 / 本次接上 / 还缺）+ 一份可读报告；
· 可选把找到的素材收进 Footages；可选跑完把本次启动的 AE 关掉；可选缺件时全盘补搜；
· 出问题能一键导出诊断包（本机 zip，不上传）。

不干的事：不改 AE 安装目录、不动系统设置、不联网上传任何东西。

================================================================
怎么用（三步）
================================================================

1. 双击 拾链.exe（别把 exe 单独拖出去，它要旁边的 _internal）。
2. 点【选工程】挑一个 .aep。素材搜索目录一般会自动推断好，不对再自己加。
3. 点「开始修复」。跑完看结果那一行：「接上 N 条，还缺 M 条」。点【工程文件夹】看 again_fixed.aep。

> 跑之前先把已经开着的 AE 关掉 —— AE 只能开一个实例。

================================================================
拾链 1.0.0 跟上一代（AE 素材医生 v1.9.8）有什么不一样
================================================================

1) 启动 AE 的方式换了 —— 不会再「跑完 AE 自己消失」
   老版本用 AE 的 -r 参数跑脚本，脚本一结束 AE 就自己关掉（这是 AE 的行为，不是本工具的）。
   这一版改成「正常启动 AE + 往 AE 的 Startup 目录放一个一次性小程序」：
   脚本跑完自己删掉，AE 留在原地可用。
   万一某台机器上这条路走不通，会自动退回老办法，并在日志里写一行 FALLBACK 说明原因。

2) 日志不再写进工程目录
   过程日志写在软件自己的目录：
       %APPDATA%\AE素材医生\logs\relink-<工程名>-<时间戳>.log
   日志卡右上角有「日志文件夹」，一键直达。

3) 工程根目录干干净净
   跑完之后，工程目录里只会多一个 again_fixed.aep 和一个隐藏目录 .ae_doctor\：
       .ae_doctor\_relink_report.json     这次哪些接上了、哪些没接上
       .ae_doctor\_relink_missing.txt     没接上的清单（没有缺件时不会生成这个文件）
   临时文件（脚本、索引）跑到一半放在软件目录，跑完就删。

4) 界面是一整屏，不用一步步点
   工程、素材目录、选项、三宫格结果、过程日志全在同一屏。
   结果那一行直接给结论，例如「接上 21 条，还缺 11 条，另有 1 条是按同名文件猜的，可能要核对」。

5) 更新软件之后，界面上会出现一条提示，点「立即重启」就换成新版
   不点也不会出错，只是继续用旧的那份。修复跑着的时候按钮会先置灰。

================================================================
两条硬前提（一代踩过，写在最前面）
================================================================

甲、这个版本**必须**是「一个文件夹 + 里面一个 exe」的形态（--onedir）。
    不要把它压成单独一个 exe（onefile）。这台机器的 %TEMP% 不能写，
    压成单文件的版本一定起不来 —— 双击没反应、或者报错一闪就没。

乙、AE 只能开一个实例。
    如果已经开着 AE，本工具会先提示：结果行写「AE 已经开着，先关掉再点开始」，
    主按钮变成「关掉了，重试」，日志里一行 SKIP 点名 PID。
    不是本程序启动的 AE 一律不碰，也不会硬往里塞脚本。关掉 AE 再点一次就行。

================================================================
界面上的几个开关是什么意思
================================================================

· 只检查，不改工程
    只看不写。跑完给报告，工程文件一个字节都不动。

· 先复制一份再改
    默认勾上。先复制出一个 again_fixed.aep，所有修改写进副本，原工程保持原样。
    不勾就直接改选中的那个工程文件（不推荐）。

· 跑完保存工程
    默认勾上。跑完在 AE 里按 Ctrl+S 把结果存进工程；取消勾选就只改不存。

· 素材收进工程
    一个下拉，三个选择：不收进 / 复制到 Footages / 移进 Footages。
    把找到的素材统一收进一个文件夹，方便以后搬工程。
    「移进」会动原素材的位置，不确定就选「复制」。

· 跑完关掉本程序启动的 AE
    默认不勾。勾了才会关掉**本程序这次自己启动的那一个** AE（按进程号），
    不是本程序启动的 AE 一律不动。

· 没找到就全盘搜
    按搜索目录找不到时，再问一次本机的 Everything 索引（全盘找）。
    慢一点，但漏得少。只按文件名匹配，同名文件可能认错，跑完看日志里「补搜」那几行。

================================================================
v1.0.1 改了什么
================================================================

· 诊断包里的崩溃事件以前印成「?  id=? 」（只有原始文本、没拆字段），现在能直接看到
  时间 / 事件 ID / 来源 —— 出问题发这个 txt 就够，不用再翻系统日志。
· 命令行（--cli）的控制台输出顺序整理过：以前 Python 的「完成」会插在脚本回显的
  「汇总」前面，看着像日志顺序坏了；现在一定先出汇总、再出完成。日志文件本身顺序没变。

v1.1.0 改了什么
================================================================

· 新增「替换映射…」（在工程卡右下）：认不出的素材可以手工指到本机某个文件 ——
  改过名的、换了扩展名的、只有一半名字对的，都能这么救。指过一次就记住，
  下次同一个工程直接照它接，不用再指。
· 「这次还缺的」可以直接在同一个窗口里一条条指定替身：选中一条 → 点「指定替身…」→
  挑出你本地那份，立刻生效。
· 靠映射接上的会算进「接上 N 条」，报告里另记一个 mapped 数（界面结论行也会提一句）。
· 映射指错/目标文件被移走时，日志如实写「映射表指向的文件不存在: <路径>」，
  不会退回自动匹配假装接上 —— 免得你以为「我指的没生效」。
· 命令行多了 --mapping <文件>，可以指定另一份替身表（默认用
  %APPDATA%\AE素材医生\mapping.json）。

v1.1.1 改了什么
================================================================

· 打开工程时 AE 弹的「有文件找不到」提示框，现在会自动按掉继续 —— 以前它会把
  打开动作卡住，你看到的是「AE 开着但什么都不动」。如果那个框里有「搜索 / 定位 /
  取消」这类按钮，程序**不会**替你点（点了可能半开工程或再弹一个文件浏览器），
  只在日志里写一句让你手动处理。
· 彻底丢失的素材也能记住「它原来在哪」了（以前这种条目在缺件清单里只剩占位符），
  所以「替换映射…」里按原路径指定替身更准。
· 同名文件有好几个时，优先选**原来所在目录相同**的那个，而不是「谁先扫到用谁」；
  日志的匹配方式会写成「同目录优先」，方便你核。
· 接完会复查一次：如果 replace 没报错但 AE 仍把素材标成离线，日志写
  RELINK-SUSPECT（只是提示，不改统计口径）—— 这类「假装接上」以前是看不出来的。

v1.1.2 / v1.1.3 改了什么
================================================================

· 认出「AE 卡死」并尽早报错：打开工程时如果 AE 的界面线程整个无响应，
  25 秒后就会提示「无响应（卡死，不是启动慢）」，最迟 75 秒判失败并说明常见原因
  （插件冲突、字体解析、网络盘掉线）—— 以前会一路干等到 4 分钟，看着像「怎么这么慢」。
· 软件里的图标换成正式那枚（深蓝底双环 + 橙色闪电），标题栏与任务栏都换了。
  以前窗口里是个「紫圆 + 白十字」的占位图，跟桌面图标对不上，像两个软件。

v1.1.4 改了什么
================================================================

· 「崩溃修复选项」这类框以前只按一次回车，按不掉就没机会了；现在按完会复查，
  框还在就再按一次（真实键盘输入优先，自绘窗口才收得到），并如实记一句。
· 同一套逻辑也用在「解析字体」「打开项目」与缺素材提示框上。

v1.1.5 改了什么
================================================================

· 诊断包在打包时就打码：本机用户名、机器名、SID 一律换成 <user> / ****，
  日志里的 C://Users//<你的名字>//... 也一并替换。包是拿去发给别人的，这一步不该让你自己来做。
· 重连 .psd / .psb / .ai 之后，日志会多一行「请核对图层结构是否完整」。
  AE 里没有可靠的办法判断"这张图当初是不是分层导入的"，所以宁可多提示一句，
  也不让日志写着成功、实际图层已经塌了。
· 注意：分层 PSD/AI 请手动替换素材并勾 Composition - Cropped Layers，脚本救不了图层。

v1.1.6 改了什么
================================================================

· 状态行会告诉你进度：「正在重连… 17/32  26s」，不再只有一个转圈 —— 大工程也能判断
  是"在跑"还是"卡了"。
· 新增【只重试缺件】：跑完如果还缺，补齐素材之后点它，只重跑缺的那几条，
  不重扫全盘、不开第二遍全量比对。命令行对应 `--only-missing`。
· 说明：这个按钮用的是工程 `.ae_doctor\` 里上一次的缺件清单，所以要先完整跑过一次。

v1.1.7 改了什么
================================================================

· 图像序列（img_0001.png 这类）不再"接上了但可能不对"却说不出话：
  接完会核对同目录帧数与帧号，日志分别写 SEQ-OK / SEQ-OFFSET / SEQ-WARN。
  帧号变了（原来 0005、接成 0001）会明确说"接上后可能整条错位"。
· 一次可以处理多个工程：命令行写 `--cli 甲.aep 乙.aep D://项目目录`，
  界面上「选工程…」按住 Ctrl 多选。跑完一个自动接下一个，最后给一张汇总表
  （哪个成功、哪个失败、共接上多少条）。单个失败不会打断其余。
· 命令行多了 `--json`：stdout 只打一坨结构化结果（含 stats/mapped/missing/warnings/路径），
  日志走 stderr。批处理或接别的工具时用得上。
· AE 卡死时会把现场存下来（`hung-日期时间.txt`，在日志目录里）：
  当时开着哪些窗口、哪个无响应、插件目录清单（按修改时间倒序）。下次复现直接发这个文件。
· 「替换映射…」保存改成三方合并：界面开着、中间又跑过命令行时，
  不会再把对方新增的条目整表吃掉（也不会让删掉的条目"复活"）。
· 接上之后仍提示需要核对的几类（序列帧号、分层 PSD、疑似没真接上、0 字节文件）
  会直接出现在结果区，不用翻日志找。

v1.1.8 改了什么
================================================================

· 认不出的模态框（例如 AE 的「设置窗口」）不再把工程卡死在打开这一步：
  这类框只有一个标题、没有原生按钮，脚本一行都写不出来。现在会用 **Esc** 关掉它，
  并在日志写一行「有个不认识的框挡在前面：『设置窗口』，已按 Esc 关掉」。
  Esc 等于"取消"，不改设置、不删工程、不提交任何东西；一次最多关两个，同一个框只关一次。
· 「崩溃修复选项」按不动的老毛病：以前只发回车，日志写着"已按「继续」"、其实框还在
  （自绘对话框会吞掉伪造按键）。现在回车没反应就**自动用鼠标点**「继续」——
  先点标题栏把窗口激活（正文一个像素都不碰，不会误选「安全模式 / 重置首选项」），
  再点右下角那个「继续」。两种都点不动才提示你手点，且会如实写进日志。
· 被插件自己的窗口卡住时会**点名**：日志直接说「挡路的是插件自己的窗口：『Optical Flares』」，
  并给出三条处置办法（换插件 / 临时挪走 .aex / 换 AE 版本），不再让你以为是缺素材。
  这种情况下 20 秒就收场，不再干等 10 分钟。
· 真卡死的判据加了一条「CPU 有没有在动」：只有"主窗口不回消息 **且** 进程不吃 CPU"
  才算卡死（30 秒收场）。打开大工程时主线程忙着读盘、窗口一样不回消息 —— 那种不会被误判。
· AE 自己退出后不再白等：以前 AE 没了，命令行还会傻等十几分钟才报超时。
  现在连续 10 秒查不到 AfterFX 就判「这次没接上」，并说明日志最后停在哪。
  判据是"有没有任何 AfterFX"，所以 AE 崩溃后自己重启（PID 变了）不会被误杀。
· 上面两种情况在 `--json` 下也会照常输出一坨结果（`ok:false` + 原因），
  不会出现"超时了、stdout 一个字都没有"。

================================================================
日志怎么看
================================================================

日志区显示的是中文短标签：重连 / 缺失 / 跳过 / 已启动 AE / 等待脚本 / 补搜 / 汇总 …
日志文件里存的是排障用的机器标签：RELINK / MISSING / SKIP / LAUNCH / A2 / INDEX / SUMMARY，
两者一一对应，屏幕上换个说法而已，文件内容没变（发给别人排查时用文件那份）。

================================================================
出问题了怎么办
================================================================

1. 先看界面下方那几行日志 —— 它把这次干了什么、卡在哪一步都写下来了。
2. 点「导出诊断包」，会把日志、设置、系统信息、AE 安装与签名状态、最近 7 天的崩溃事件
   打成一个 zip（%APPDATA%\AE素材医生\拾链-diag-<时间戳>.zip）。这个包**不上传**，在本机，
   发给帮你排查的人就行。
3. 常见三种卡法（日志里会直接说）：
   · 一个 AfterFX 进程都没有 → AE 根本没起来（多半是安装/权限问题，先手动双击一次 AE）
   · 进程在但窗口没出来 → 卡在初始化（等 Adobe 账号对话框、崩溃恢复、缺字体、插件初始化）
   · 有窗口但脚本没开始 → 多半是 AE 弹了个对话框挡在前面，点掉它

4. 一种很好认的对话框：**标题栏是空的**，里面有四个按钮（以安全模式启动 / 重置首选项 /
   管理增效工具 / 继续）。这是 AE 的「崩溃修复选项」——上次 AE 没正常关掉才会出现。
   点「继续」就行（默认按钮就是它），**不要**点「以安全模式启动」或「重置首选项」，
   那两个会改掉你自己的 AE 设置。拾链遇到它会自己点「继续」，也自己会点掉「解析字体」
   「打开项目」这类启动期进度框 —— 但如果你手动开着 AE 撞上了，知道点哪个就好。

5. 缺件怎么看：结果行说「还缺 M 条」时，点【缺失清单】（没有缺件时它是灰的），
   或者在工程目录找 .ae_doctor\_relink_missing.txt，每行是「文件名 ⇥ 原来在哪」。
   日志里对应的行是「缺失」；标「按同名文件猜的」那几条建议人工核对一眼。

6. 如果日志里出现「复制工程失败 … Permission denied」：不是软件坏了，是它被从
   一个受限的上下文（受限目录、受限账户、某些同步盘目录）启动，继承到了不许写的权限。
   把 拾链 放到普通目录（例如桌面或 C:\插件\…）再双击；**别从受限目录直接运行它**。
   实在要命令行跑，请在工作目录正常的控制台里跑。
